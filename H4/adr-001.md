# ADR-001:Fusión de Factory y Observer para pagos y stock
## Contexto:
El sistema de tienda con inventario necesita manejar distintos métodos de pago y, también reaccionar automáticamente cuando el stock de un producto disminuye hasta un nivel mínimo.
## Decisión:
Se fusionaron los patrones Factory y Observer. Factory se encarga de crear el método de pago, mientras Observer detecta cambios en el stock y envía una notificación  al administrador o encargado de inventario cuando existe stock bajo.
## Alternativas consideradas:
También había considerado usar Strategy (H3/con-strategy) ya que me podía servir para los diferentes tipos de descuentos. Sin embargo preferí usar Factory porque mi principal necesidad era crear los distintos métodos de pago, y junto a Observer, para enviar la notificación una vez realizado el pago, y también para el stock.
## Consecuencias:
- Se obtiene un sistema preparado para crecer, porque se puede agregar nuevos métodos de pago y también otras formas de notificación.
- Desventaja, se necesita aumentar la cantidad de clases e interfaces, haciendo que la estructura sea mas compleja.
